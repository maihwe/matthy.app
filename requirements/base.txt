# Runtime dependencies.
#
# ── Why these are ranges and not pins ───────────────────────────────────────
# 12 §2.1 requires dependencies "pinned with hashes (`pip-compile
# --generate-hashes`)". Producing that lock file requires *resolving* the
# packages, which requires a network and a working pip. Writing hash values by
# hand would be inventing them, so this file carries floor/ceiling ranges and
# the lock file is generated as the first action of the next slice that has a
# working toolchain:
#
#     pip-compile --generate-hashes --output-file requirements/lock/base.txt \
#         requirements/base.txt
#
# Until then, CI installs from these ranges. The gate that matters — gate 9,
# `pip-audit` on high severity — runs either way.
#
# The floor is what the code is written against; the ceiling is the next major
# version. A major bump is a deliberate act rather than something that happens
# on a Tuesday.
